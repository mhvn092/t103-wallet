FLOW 1 IRT Deposit → Simulator PSP Pay → Callback/Verify → Wallet & Ledger

1) Calls POST /deposits with 500,000 IRT and an Idempotency-Key. 2) Rewrites http://simulator:8080 to your Simulator Base URL and calls POST /psp/pay/{token} with {"result":"success"} (if simulator CORS blocks browser fetch, it prints the exact curl command and also lets you trigger POST /webhooks/psp/callback). 3) Polls GET /deposits/{id} and checks GET /wallets/{userId} + GET /wallets/{userId}/ledger.

FLOW 2 IRT Withdrawal → Hold → Cancel OR HMAC-Signed Payout Webhook

1) Credits user via POST /internal/adjustments (300,000 IRT) so balance is funded. 2) Calls POST /withdrawals (150,000 IRT to IBAN IR820540102680020817909002) — moves funds from available to locked and reserves daily limit. 3) Either cancel immediately while in PENDING_DISPATCH (POST /withdrawals/{id}/cancel) OR send an HMAC-SHA256 signed POST /webhooks/payout (SUCCEEDED / FAILED).

BONUS FLOW 3: USDT Withdrawal (TRC20 + 1 USDT Fee) & P2P Transfer

1) Credits 50.000000 USDT to Primary User via POST /internal/adjustments. 2) Transfers 12.500000 USDT atomically to Second User via POST /transfers. 3) Withdraws 15.000000 USDT to TRC20 TQn9Y2khEsLJW1ChVWFMSMeRDow5KcbLSE (locks 16.000000 USDT = amount + 1 USDT fee, checks 200M IRT daily limit at 60,000 IRT/USDT).

FLOW 4 Idempotency Replay / Key-Reuse Mismatch & Concurrency Burst

Tests the two core financial invariants live: Idempotency: sends the same Idempotency-Key twice with identical body (must return same ID), then a third time with a different amount (must return 422 IDEMPOTENCY_KEY_REUSED).
